Zero-Knowledge Privacy That's Actually Quantum-Safe

Most ZK systems (Groth16, PLONK) rely on BN254 pairings — broken by quantum computers. Zeno's shielded pool uses BLAKE3 hash-based commitments with no trusted setup required.

  • Shield: commit value into the private pool
  • Transfer: spend a commitment, create a new one
  • Unshield: withdraw to public balance
  • Nullifier prevents double-spend
  • ZK verify precompile at 0x10003

Consensus

How Zeno Reaches Finality

A four-phase BFT protocol. Every signature is ML-DSA. Every block is final.

01

Propose

Deterministic proposer builds a block from the priority mempool, signs with ML-DSA, and broadcasts. Block size enforced at 2MB.

02

Prevote

Validators verify the proposal and cast ML-DSA-signed prevotes. Tendermint locking rules prevent conflicting votes across rounds.

03

Precommit

When 2/3+ prevotes agree (polka), validators lock on the block and emit precommit votes. Lock state persisted to WAL for crash recovery.

04

Finalize

With 2/3+ precommits, the block is atomically committed via RocksDB WriteBatch. Instant finality — no reorgs, no confirmation delay.
